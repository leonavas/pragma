One store, two components

p-shelf and p-basket never talk to each other: both read and change shared.cart.

lib/state/cart.js has no imports and no exports: let lines is the state, count and totalLabel are derived, add and remove change it. HTML reads it as {shared.cart.count} and <for line in shared.cart.lines>; a script imports shared from 'pragma' and calls shared.cart.add(product). Importing the store file itself fails check with js/store-import.

Without persist a store lives in memory: it survives client navigation between pages (try another section and come back) but not a reload. Any page or component can read it, including _layout.html, which has no script of its own.

persist: drafts that survive reloads, synced across pages

export const persist = ['draft', 'pinned'] keeps those two lets in localStorage['pragma:scratchpad'].

The store restores the listed values when its module loads and writes them back after each render. It also listens to the storage event, so every other tab of the same origin follows live: type in either textarea, then reload the page. Persist preferences, drafts and local-only data, never anything the server owns. persist is the only export a store may have.

A store read only from a script

A derived function can read a store, and it runs again on every render.

p-shipping never mentions the cart in its HTML: remaining() calls shared.cart.total() and the HTML shows {$message}. In a script, a store's derived values are functions you call; in HTML they are paths. The build ships a store to every page that reaches it, from HTML or from a script, and a shared.x with no lib/state/x.js fails check.
