One store, two components

store(object) from core/state.js returns the object itself: plain fields for state, getters for derived values (count, totalLabel), methods for mutations used by more than one place. p-shelf and p-basket never talk to each other; both read and write shared.cart, and every action re-renders the whole page, so both stay in sync.

Without persist the store lives in memory: it survives client navigation between pages (try another section and come back) but not a reload. Any page or component can bind it, including _layout.html, which has no .js of its own.

persist: drafts that survive reloads, synced across pages

store(object, { persist: 'scratchpad' }) restores the object from localStorage['pragma:scratchpad'] when the module loads and writes it back after each render, getters excluded. Use it for preferences, drafts and local-only data, never for anything the server owns.

Persisted stores also listen to the storage event, so every other tab of the same origin updates live. The frame below is a separate route, demo/scratchpad.html, with no .js; type in either textarea and watch the other one follow, then reload the page.

A store read only from JavaScript

The build ships a store to every page that references it: a shared.x path in HTML, ctx.shared.x in a page or component module, or a static import. p-shipping never mentions the cart in its HTML; its getter reads ctx.shared.cart.total and the HTML shows $message. A shared.x with no lib/state/x.js fails check with html/invalid-root.

Getters in a component can read stores freely, because they run on every render. Add items to the cart above and this line follows.
