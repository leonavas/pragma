load() with a skeleton

routes/catalog.server.js runs on the server, next to the page routes/catalog.html. Its load function returns the data, and the page reads it as data.products. While load runs, page.loading is true, so the page shows a skeleton block.

  • load gets the request context: params, query, request, cookies, env, log and more.
  • A query change is a navigation, so load runs again.
  • A file named _name.server.js is a private helper. It never reaches the browser.

When load fails

error(503, 'message') from 'pragma/server' stops load with that status. The page gets it as page.error, so the <else-if page.error> branch shows.

ssr = true: data in the first HTML

With export const ssr = true, the server runs load and sends the page with its data in the HTML. There is no skeleton, and search engines see the data.

Writes go through server actions

A server action writes data. call('sign', input) runs actions.sign in the .server.js file and returns its result; the page assigns it to data. new FormData(event.target) reads the form fields.

Every form is also a tool for AI agents in the browser (WebMCP). toolname, tooldescription and toolparamdescription describe it, and event.respondWith gives the agent the result.
