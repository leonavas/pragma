load() with a skeleton

routes/catalog.server.js runs on the server, next to the page routes/catalog.html. Its load function returns the data, and the page reads it as data.potions. While load runs, page.loading is true, so the page shows a skeleton block.

  • A query change is a navigation, so load runs again.
  • A file named _name.server.js is a private helper. It never reaches the browser.

When load fails

error(503, 'message') from 'pragma/server' stops load with that status. The page gets it as page.error, so the <else-if page.error> branch shows.

ssr = true: data in the first HTML

With export const ssr = true, the server runs load and sends the page with its data in the HTML. There is no skeleton, and search engines see the data.

The server context: cookies and more

load and every action get one context object. cookies.get reads a cookie of the request and cookies.set adds it to the response. A cookie is httpOnly, sameSite: 'lax' and secure by default.

The context also has request, url, params, query, env (secrets and bindings), log, locals, setHeaders and waitUntil.

Writes go through server actions

A server action writes data. call('sign', input) runs actions.sign in the .server.js file and returns its result; the page assigns it to data. new FormData(event.target) reads the form fields.

Every form is also a tool for AI agents in the browser (WebMCP). toolname, tooldescription and toolparamdescription describe it, and event.respondWith gives the agent the result.

When an action fails

error(409, 'message') in an action makes call throw. The error has status, body (what the server sent) and message, so the page can react to each status.

Redirects: redirect()

redirect(303, url) from 'pragma/server' sends the browser to another page. After an action, the page navigates before call returns. In load, it replaces the current page, so Back skips it.

Middleware: before every request

routes/_middleware.server.js runs before every page, load, action and endpoint. It is the place for auth: it puts the user in locals for load and the actions, and redirects when a path needs a user. next() gives the response, which it can change.

An app has one middleware, so this site cannot run this one. The output is real, from a new app with this file.

curl -sI localhost:5197/account
HTTP/1.1 303 See Other
location: /login

curl -sI localhost:5197/
HTTP/1.1 200 OK
x-frame-options: DENY

Endpoints: a .server.js without a page

A .server.js with no .html next to it is an endpoint. It exports GET, POST and the other methods, and each returns a Response: a file, a stream, a webhook reply. A link with download opens it without the router.

Page data comes from load, and writes go through actions. Do not make /api endpoints for them.

Stream from an action: stream()

An action can return a Response with a ReadableStream. With content-type: application/x-ndjson, each line is one JSON value. stream('ask') gives each line as soon as the server writes it, in a for await loop.
