Text: {path}

{$name} is the only way to put a value in text, and it works inside attribute strings too: title="Profile of {$name}", href="#user-{$slug}".

  • Only paths go between the braces: $x, data.x, shared.cart.total, params.id or a <for> variable. A function from the script is a derived value: {$length} calls length() on every render.
  • Values are escaped; null and undefined print nothing. A page with ssr gets them in the first HTML; otherwise the runtime fills them at boot, and the raw {…} never shows.
  • Braces are literal text inside <code> and <pre>, which is how this page shows them. Anywhere else, \{ writes a literal brace.
  • For a whole value or a boolean attribute use :attr instead (:disabled="$offline"). {} is not allowed in class (use .name) or in a component prop (pass a path: :title="$title").

Values are paths, never expressions

Every directive takes a path of the form root.a.b. The roots are $x (a name from the owner's script: state, prop, constant or function), data (the load result), shared.store, params, query, page.loading / page.error and the variable of an enclosing <for>. Properties work, so $items.length is fine; calls, indexes and operators are not.

The only operator is !, and only in <if>, <else-if>, :show and .class. Anything derived (a total, a label, an aria-* string) is a function in the script, const total = () => …, which is what every example below does.

Bindings: :attr, :aria-*, :data-*

:href, :title, :disabled or any other :attr sets the whole attribute: false, null and undefined remove it, true sets it empty. Toggle the switch: while the service is down the link has no href at all.

aria-* states need the strings 'true' / 'false', because boolean false removes the attribute. :data-tone is the hook for a style with many values: the component's CSS selects [data-tone="ok"] without touching classes. Only the bound form is allowed; a hand-written data-tone="ok" fails check with html/data-attribute.

Class toggles: .class and .class="!v"

.line-through="$done" adds the class while the value is truthy; .is-pending="!$done" does the opposite. The class must be a known utility or a class from the project's CSS, and variants work: .md:font-semibold only bolds from 48rem up. Static classes on the same element are left alone.

There is no :class and no {} inside class: both are check errors (html/class), because a computed class name could never be generated into the CSS. Write the static classes in class and toggle each optional one; for a value with many states, bind :data-tone and style the attribute, as the bindings example does.

:show hides, <if> creates

:show toggles the hidden attribute, so the element, its listeners and its input state stay in the DOM. <if> inserts and removes its content. An element with autofocus inside a block that was just inserted receives focus, so opening the right pane puts the caret in its input.

Two-way binding with :model

:model works on input, select and textarea, and only with a $x or shared.x path. The value keeps its type: checkboxes are booleans, radios hold the value of the checked one, number and range give a number (or null when the field is empty), everything else a string. A prop cannot be the target (js/prop-write).

Events: event by default, el on request

@keydown="pressed" calls the script's function with the DOM event, so function pressed(event) needs no wrapper. With parentheses the function receives only what is listed: @focusout="record('@focusout', 'field lost focus')", @change="toggle(item)", @dblclick="doubled(el, event)". el is the element that has the directive.

  • An argument is a path (item, $draft, data.x), a string in quotes, a number, true, false, null, event or el. Expressions are a check error.
  • Double-click the bold word: event.target is the <strong>, el is still the <p>. Use el instead of an id lookup; event.currentTarget is the root the runtime listens on.
  • A store function is a handler too, with no wrapper in the script: @click="shared.cart.remove(line)" (Stores).
  • @submit calls preventDefault() for you, so the form never reloads the page.
  • The same function can be an action and a helper: record runs from @focusout and from the other functions.

Overlay shortcuts: @open and bare @close

@open="id" opens the overlay with that id and @close, written without a value, closes the overlay around it. The button's value becomes the result of confirm(id); the overlays section covers modal, alert and dropdown in depth.

Conditions: <if>, <else-if>, <else>

The path in a block tag is unquoted: <if $loading>, <else-if $noOrders>. Any number of <else-if> may follow, and each one must come right after the closing tag of the previous branch. Every block holds exactly one root element, which carries the directives; the block tag itself takes none.

Lists: <for> with key, and <empty>

<for item in group.items key=item.id> repeats its root element; the key is required, starts with the loop variable and must be unique (duplicates throw in dev). Updates diff by key. <empty> right after </for> renders when the list is empty.

Pass the item to the function: @change="toggle(item)", @click="clear(group)". State is a deep proxy, so item.done = !item.done and group.items = [] render without copying anything. A loop variable cannot shadow a root such as data or page.

Static props decide <if> at build time

In a component without a script, <if $icon> on a static prop is resolved by the compiler. The badge with icon ships the star inline and the other ships nothing, with no template and no runtime work. A bare attribute such as icon is true; icon="", icon="false" and a missing one are false.

What the compiler rejects

The list above is closed, so pragma check rejects what falls outside it, and every error names the fix:

  • The old API: :text (html/text-removed), export const state and actions, ctx.$, ctx.update and export function mount(ctx) (js/legacy-api).
  • Expressions in paths and in event arguments, {{ }} and ${ }, hand-written data-*, inline style and on*, :class, quoted block paths and a <for> without key.
  • Attributes from other frameworks, with the pragma form in the message: Vue's v-if, Alpine's x-show, Svelte's on:click, Angular's *ngIf, React's className.
  • Script mistakes that would show a stale value: data at the top level, a let derived from another let, a derived function used without () and $name in JS (State: script mistakes).
