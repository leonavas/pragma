Values are paths, never expressions

Every directive takes a path of the form root.a.b. The roots are $x (the owner's state or prop), data (the load result), shared.store, params, query, page.loading / page.error and the variable of an enclosing <for>. Properties work, so $items.length is fine; calls, indexes and operators are not.

The only operator is !, and only in <if>, <else-if>, :show and .class. Anything derived (a total, a label, an aria-* string) is a getter in the .js, which is what every example below does.

Bindings: :text, :attr, :aria-*, :data-*

:text sets escaped text content; the fallback text inside the tag ships in the prebuilt HTML. :href, :title, :disabled or any other :attr sets the attribute: false, null and undefined remove it, true sets it empty. Toggle the switch: while the service is down the link has no href at all.

aria-* states need the strings 'true' / 'false', because boolean false removes the attribute. :data-tone is the hook for a style with many values: the component's CSS selects [data-tone="ok"] without touching classes. Only the bound form is allowed; a hand-written data-tone="ok" fails check with html/data-attribute.

Class toggles: .class and .class="!v"

.line-through="$done" adds the class while the value is truthy; .is-pending="!$done" does the opposite. The class must be a known utility or a class from the project's CSS, and variants work: .md:font-semibold only bolds from 48rem up. Static classes on the same element are left alone.

There is no :class: it is a check error (html/class), because a computed class name could never be generated into the CSS. Write the static classes in class and toggle each optional one; for a value with many states, bind :data-tone and style the attribute, as the bindings example does. .bg-primary-500/50="$x" is rejected too, since / ends an attribute name; use a custom class instead.

:show hides, <if> creates

:show toggles the hidden attribute, so the element, its listeners and its input state stay in the DOM. <if> inserts and removes its content. An element with autofocus inside a block that was just inserted receives focus, so opening the right pane puts the caret in its input.

Two-way binding with :model

:model works on input, select and textarea, and only with a $x or shared.x path. The value keeps its type: checkboxes are booleans, radios hold the value of the checked one, number and range give a number (or null when the field is empty), everything else a string.

Events with @event

@name="action" calls the owner's actions.action(ctx) for any lowercase DOM event: @input, @keydown, @focusout, @dblclick. The event is ctx.event and the element is ctx.el. @submit calls preventDefault() for you, so the form never reloads the page.

Overlay shortcuts: @open and bare @close

@open="id" opens the overlay with that id and @close, written without a value, closes the overlay around it. The button's value becomes the result of ctx.confirm; the overlays section covers modal, alert and dropdown in depth.

Conditions: <if>, <else-if>, <else>

The path in a block tag is unquoted: <if $loading>, <else-if !$orders.length>. Any number of <else-if> may follow, and each one must come right after the closing tag of the previous branch. Every block holds exactly one root element, which carries the directives; the block tag itself takes none.

Lists: <for> with key, and <empty>

<for item in group.items key=item.id> repeats its root element; the key is required, starts with the loop variable, may be written with or without quotes and must be unique (duplicates throw in dev). Updates diff by key. <empty> right after </for> renders when the list is empty.

In an action the current item is ctx.scope.item; nested loops expose every variable, so clear reads ctx.scope.group. A loop variable cannot shadow a root such as data or page.

Static props decide <if> at build time

Inside a component, <if $icon> on a static prop is resolved by the compiler. The badge with icon ships the star inline and the other ships nothing, with no template and no runtime work. A bare attribute such as icon is true, both here and as ctx.$.icon in a component's JS; icon="" and icon="false" are false.

What the compiler rejects

The list above is closed, so pragma check rejects what falls outside it: hand-written data-* and state.x, expressions in paths, inline style and on*, :style, :class, {{ }} interpolation (allowed as text only inside <code> and <pre>), quoted block paths and a <for> without key. Each error names the fix. The only markers you write are data-page and data-reload.

Attributes from other frameworks fail too, with the pragma form in the message: Vue's v-if, Alpine's x-show, Svelte's on:click, Angular's *ngIf, React's className.
