Each input type gives its own value

:model keeps the type of the value. A number or range input gives a number, a checkbox gives true or false, and a group of radios gives the value of the checked one.

Each field has a label: a <label> around it, or a <legend> for a group.

Select: native first

A native <select> works with the keyboard, with screen readers and on phones. :model holds the value of the option, not its label. Style the box with utilities; do not change its appearance.

A styled list: c-select

When the list needs its own look, use <c-select>. It is in lib/components/select/ of every new app. It opens a dropdown and keeps a hidden native <select name> in sync, so new FormData(event.target) reads it like any field.

Every form is also a tool for agents, so it has a toolname and a tooldescription. WebMCP explains them.

Validation: browser rules, then yours

Native attributes come first: required, type="email", min, minlength. The browser stops the submit and shows its message, so @submit runs only with valid fields.

A rule between two fields goes in the submit function. It puts its message in state, in a role="alert" element.

Submit to a server action

Some rules need the server, for example a callsign that must be free. The action stops with error(409, message), and call throws: failure.message is the text for the form. The guestbook shows the success path.
