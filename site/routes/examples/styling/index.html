Utilities, variants and what check rejects

The card below is styled only with utilities. Variants are hover:, focus:, focus-visible:, active:, disabled:, group-hover:, dark: and the breakpoints sm: to 2xl:; they combine (md:hover:bg-primary-600), and colors take an opacity (bg-accent/20). The palette is white, black, transparent, current and the scales neutral, primary, danger, success, warning in shades 50 to 950, and the full list is .pragma/docs/classes.md.

Anything else is a check error, not a silent no-op: arbitrary values, negative utilities, unknown classes such as shadow-inner, and style="…". The other tabs show the output.

Tokens generate utilities

Each --color-<name> or --color-<name>-<shade> in @layer tokens becomes bg-, text-, border- and the other color utilities. These swatches use this site's own tokens; redefining --color-primary-* rebrands every primary utility at once. The starter ships theme-aware bg-surface, text-ink, text-muted, border-line and the classes .card, .btn, .btn-primary, .btn-danger, .dialog.

The redefinable tokens are --color-*, --font-sans, --font-serif, --font-mono, --radius-*, --shadow-* and --spacing. A new font name such as --font-display does not create font-display. .pragma/base.css also reads --page-bg, --page-fg and --skeleton-bg, which switch in dark mode, plus --container-* for the max-w-* sizes.

Component CSS, scoped by the build

A component's <style> is for what utilities cannot say: here, :has(:checked) drives the selected segment and a custom property that sets the row padding, with no JavaScript at all. Write plain selectors: the build scopes each one to the component.

  • The build marks the root with data-c and adds a :where(…) that matches the root and everything inside it to the last part of every selector, as the app.css tab shows: .density-option:hover or even li never styles anything outside the component, and the scope adds no specificity.
  • Only the last part is scoped, so an outside ancestor needs nothing special: html[data-theme="dark"] .density-option still matches only this component's options.
  • The root is [data-c="density"], and a selector that names it stays as written. :global(…) opts out only what is inside it: .density-rows :global(.hit) keeps .density-rows scoped and lets .hit match anything inside it, child components included. A selector that is all :global, such as :global(:root) { --row-pad: 1rem; }, is global.
  • A page's <style> is scoped to its <main data-page> the same way. All of it goes into @layer components of the single app stylesheet; a separate density.css works the same, and having both is a check error.
  • For a p- component the build makes the scope unique per folder (density-97d4f0 in the tab), so two private components with the same name never share a rule. Forbidden: !important, ID selectors and external @import.

Dynamic styles: .name toggles and data-*

There is no :class and no style: every class name is written out in the source, so check can validate it and the build can generate it. Toggle a class on a condition with .text-accent-text="$passed". When the value itself varies, bind a data-* attribute (:data-status="$status") and style each value with an attribute selector in the component's <style>. Only the bound form is allowed: a hand-written data-status="ok" fails check with html/data-attribute.

Light and dark theme

Dark mode keys off data-theme="dark": tokens redefined under [data-theme="dark"] switch on their own, and palette colors pair with dark: (bg-white dark:bg-neutral-900), which matches the element or any ancestor. In an app, setTheme() from .pragma/theme.js sets it on <html> and saves it, as the theme-switch.html tab shows; importing that module also adds an inline script that restores the choice, or follows prefers-color-scheme, before first paint.

This site is dark only, so the live box sets data-theme on its own root to keep the switch inside the box. Without the .pragma/theme.js import, dark mode never activates: there is no media-query fallback. The import may also be written in the absolute form '/.pragma/theme.js'.
