Install, list, import

Any package manager works: pragma reads package.json and node_modules/. A client import must be listed under dependencies, use a quoted specifier and name what it takes. These are the three packages this page runs.

npm i valibot es-toolkit dayjs --ignore-scripts

added 3 packages, and audited 5 packages in 999ms

found 0 vulnerabilities
grep -A6 dependencies package.json
  "dependencies": {
    "dayjs": "^1.11.23",
    "es-toolkit": "^1.53.2",
    "highlight.js": "^11.12.0",
    "valibot": "^1.5.0"
  }

Each package becomes one file, /assets/npm/<package>-<hash>.js (@date-fns/tz turns into date-fns__tz), and code shared between packages goes to /assets/npm/_*.js. Pages that import it get a modulepreload for it. process.env.NODE_ENV is replaced with "production" in builds and "development" in dev.

Tree shaking, measured: highlight.js on this site

The code blocks on this site are colored by highlight.js. Importing the package index pulls in all 193 languages. Importing highlight.js/lib/core plus the three grammars the site needs is 95% less gzip: the 190 unused language modules are dropped. The core itself is not shaken: its ESM entry re-exports CommonJS, and CommonJS ships whole.

The smallest chunk is the one the browser never loads. Every showcase tokenizes in load: _source.server.js runs highlight.js on Node and sends each line with its color ranges, the section pages use ssr = true, and the mount(el) of c-showcase paints the ranges with the CSS Custom Highlight API. The code is in the first HTML and gets its colors when the component mounts, with no extra download. The client chunk exists only for the SEO page's response view, which loads it with import(); lazy chunks are not preloaded and do not count toward the page budget.

Named imports: only what you use ships

valibot is pure ESM with one module per function, the best case for tree shaking. This form imports eight names and ships 1.35 kB gzip of valibot. The schema is a constant in the <script>; validation is a derived function, so {$status} reruns it on every keystroke without any wiring.

Subpath imports share one chunk

groupBy comes from the es-toolkit index and debounce from es-toolkit/function. Both end up in a single es-toolkit-*.js of 0.43 kB gzip. The same two helpers from lodash cost 6.49 kB, because CommonJS cannot be shaken.

The debounced function just assigns two let variables: a timer firing outside an action still renders, because state is a reactive Proxy. mount() returns a cleanup that cancels a pending call when the component leaves the page.

CommonJS, loaded with import() after a click

dayjs is CommonJS, so the core and the relativeTime plugin ship whole: 3.69 kB gzip. When a package is only needed after an interaction, await import() it inside the action. The chunk is left out of the modulepreload list and the page budget, and the first paint does not wait for it.

import('pkg') always brings the whole package, so keep it for code you need all of anyway. The default export of a CommonJS module arrives as default.

What common packages cost

Gzip size of the /assets/npm/ file for each import, measured with pragma build on the packages test app in core/cli/xtask/packages/app. The runtime alone is 8.7 kB gzip per page, and the starter budgets allow 15 kB of initial JS and 10 kB per route, so chart.js only fits behind an import().

Prefer the platform first: Intl for dates, numbers and plurals, fetch, crypto.randomUUID(), structuredClone. Avoid moment, lodash, axios, uuid, nanoid and anything that builds HTML.

Also rejected, with app/package: TypeScript, JSX, .vue and .svelte files, and packages that import CSS or other assets. The same list covers Preact, Vue, Svelte, Solid, lit, jQuery and Alpine. A misspelled name is caught at check time, not in the browser, and so is an import() whose specifier is a variable.

Packages on the server

A .server.js file can import any package from package.json plus Node built-ins (node:fs, node:crypto) without listing them. Server code is not bundled: dist/server/ keeps your imports and Node resolves node_modules by walking up from it. A built-in name listed in package.json, such as the buffer polyfill, is bundled for the client like any other package.
