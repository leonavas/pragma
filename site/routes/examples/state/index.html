A page's script

Every top-level let is state, read as $visitor in HTML; every top-level function is reachable from HTML too.

{$greeting}

{$greeting} calls greeting() on every render, and @click="forget" calls forget(). A page writes its script as a <script> at the top of its .html, or as a .js with the same name; this page uses index.js because its .html is the whole article. A name in HTML that the script does not declare fails check with html/unknown-name.

Derived values are functions

Anything computed from state is a function, called again on every render, so there is nothing to keep in sync.

HTML only reads paths, never formulas, so the template asks for $perPersonLabel and the script computes it. Inside the script you call them like any function: total() reads bill() and tip(). :model keeps the input's type: a number field writes a number, or null when it is empty. Never keep a derived copy in a let that actions update.

Actions take arguments

An event calls a function by name, and inside a <for> it passes the item: @change="toggle(job)".

State is a deep proxy: job.done = true, jobs.push(…) and jobs = jobs.filter(…) all render. Arguments can be paths (job, $draft, data.x), simple literals, event or el, never expressions. An async action renders when its first part returns ("Saving…") and again after each await; renders are batched per microtask.

Props: export let, typed by the default

export let used = 0 declares a prop, and the default's type converts the attribute text.

used="72" arrives as the number 72 because the default is a number; a bare critical is true and "false" is false; a missing prop keeps its default, so the second meter's total is 100. Props are read-only: assigning one fails check with js/prop-write, so copy it into a let to change it (let count = start). That goes deep: in dev, writing into an object prop (item.done = true) throws an error that names the prop; copy it first (let draft = { ...item }). A prop the script does not declare fails at the call site with html/unknown-prop. More in Components.

mount() and its cleanup

function mount() runs once after the first render and returns the cleanup.

It is only for external effects: timers, window or document listeners, observers. mount runs only in the browser, so it is also where browser-only reads belong: the clock reads window.innerWidth there, not at the top of the script, because on an SSR page the script also runs on the server. mount(el) receives the component's root element for an observer or a measurement; read from it, never write to it. The cleanup runs when the owner leaves the DOM; for a page, on navigation. An async function mount() works too: the runtime awaits it and uses the function it resolves to as the cleanup, even when the owner left before it resolved. Never fetch data in mount; that is what load is for.

Timers and promises just assign

A callback that runs later assigns the let like an action does, and the page renders.

The action starts the interval and mount only returns the cleanup that stops it. Maps, Sets, Dates and class instances are not tracked: assign a new value instead of changing them in place.

event, el and services from 'pragma'

A handler without parentheses receives the DOM event: @keydown="inspectKey" calls inspectKey(event). With parentheses it receives only what it lists, and two names are always there: event and el, the element that has the directive. Everything else a script needs comes from import { … } from 'pragma'.

Use el instead of an id lookup or event.currentTarget, which is the root the runtime listens on, not your element. The services are shared (stores), data (the load result), params, query, page, log, call (server actions), navigate and open, close, confirm (overlays). Read data and the route inside functions, never at the top level of the script. Never write to the DOM: read event, change state and let the bindings follow.

Script mistakes that check catches

Four mistakes run without an error in the browser and show a wrong or stale value. pragma check stops each one and names the fix. This is real output for one page script:

pragma check --strict
routes/orders.html:4:16 error [js/top-level-data] `data` is read when the script starts, before the loader is done: read it inside a function (`const products = () => data.products`)
 4 |   let orders = data.orders
   |                ^
routes/orders.html:6:7 error [js/stale-derived] `label` reads `discount` once, when the script starts, and never updates: make it a function (`const label = () => discount + '% off'`) and use `$label` in HTML, `label()` in JS; or assign it in an action to change it
 6 |   let label = discount + '% off'
   |       ^
routes/orders.html:9:26 error [js/derived-call] `empty` is a function (a derived value): call it in JS: `empty()` (`$empty` without `()` is only for HTML)
 9 |   const summary = () => (empty ? 'No orders' : orders.length + ' orders')
   |                          ^
routes/orders.html:12:5 error [js/dollar-in-script] `$orders` is HTML only; in <script> write `orders`
 12 |     $orders = []
    |     ^
4 error(s), 0 warning(s)
  • js/top-level-data: data is undefined until the loader ends, so read it in a function: const orders = () => data.orders.
  • js/stale-derived: a let computed from another let or a prop is computed once. Make it a function, as in Derived values.
  • js/derived-call: in JS a derived value is a call, empty(); empty alone is the function, which is always truthy.
  • js/dollar-in-script: $ is HTML only. In the script every name is plain.

Coming from state(ctx)

  • export const state = () => ({ count: 0 }) is now let count = 0; getters are functions.
  • export const actions is now top-level functions, and ctx.scope.item is an argument: @click="remove(item)".
  • ctx.update(fn) is gone: assign the let. ctx.$.prop is export let prop.
  • ctx.data, ctx.call, ctx.log and the rest come from 'pragma'; :text is {path} inside the element.

The old API fails check with js/legacy-api, and each message names the replacement.
