Layout defaults, page overrides

A page tag replaces the layout tag with the same name, property or rel. A new tag, like canonical, is added.

Tags from server data

Use {data.x} in <title> and :content on <meta>. With export const ssr = true, the server fills the tags, so link previews see them.

Soft 404 and real 404

A [slug] route with no note still answers 200: a soft 404. Return robots: 'noindex' for that case. A URL with no route gets status 404.

robots.txt and a sitemap

Files in public/ are served from the site root. Routes produce only HTML, so sitemap.xml is a static file: write it by hand or generate it before pragma build.

Structured data with JSON-LD

Write <script type="application/ld+json"> in the page. The build moves it into <head>. With ssr, {data.x} works in its strings. This is what the server sends:

curl -s http://127.0.0.1:5181/examples/seo/demo/head-tags-from-data | grep -A6 ld+json
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Head tags rendered from server data",
  "datePublished": "2026-11-16"
}

What pragma check rejects

Head tags have one place to go, and html/head enforces it. A bound tag in the layout <head> fails too: that head is the same on every page.

pragma check
post.html:5 [html/head] bound head tags are rendered by the server so crawlers see them: add export const ssr = true to routes/post.server.js
post.html:6 [html/head] head tags are rendered by the server and read only data, params or query; "$summary"
post.html:8 [html/json-ld] invalid JSON-LD: trailing comma
post.html:12 [html/head] <meta> belongs in <head>: write it at the top level of the page fragment (or in the layout <head>)
