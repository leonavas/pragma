log in page and component scripts

Import log from 'pragma' in any page, component or store script and call debug, info, warn or error from an action or mount(). Keep the message short and fixed and put the variable parts in attributes named like OpenTelemetry's (order.id, exception.message), so records group and filter cleanly.

The runtime adds url.path, a timestamp and the page's traceId, queues the record and posts batches to /_otel. In pragma dev every call also prints to the browser console, and the dev server prints each received record as a JSON line in the terminal. debug stays in the console: the client sends info and above.

What is logged without asking

An action that throws or rejects is not swallowed: the error reaches window, and the runtime logs it as ERROR with exception.type, exception.message and exception.stacktrace. The same goes for any uncaught error or unhandled rejection on the page. Do not wrap code in try/catch only to log it again.

  • navigation (info): every client navigation, with pragma.route, push or pop, and duration_ms.
  • navigation failed and loader failed (error): a page module or a load request that failed.
  • A traceparent header on every runtime fetch (/_data, /_action), so server records join the client trace.
  • On the server, one record per request: GET /orders with method, route, status and duration in seconds; ERROR for 5xx.

log in load and server actions

load and every server action receive log in their argument. Its records carry the request's traceId and spanId, taken from the client's traceparent. A server action that throws is logged with its stack, answers 500, and call() rejects with the message on the client. pragma dev also prints server log.debug; in production it is off unless PRAGMA_LOG_LEVEL=debug.

Logging from utils/

The services from 'pragma' belong to page, component and store scripts. A plain module in utils/ imports the same client logger from core/log.js; its records join the same batches and the same trace.

import { log } from '../core/log.js'

const euro = new Intl.NumberFormat('en-IE', { style: 'currency', currency: 'EUR' })

export function formatPrice(cents) {
  if (!Number.isInteger(cents)) log.warn('price is not in cents', { 'price.value': String(cents) })
  return euro.format(cents / 100)
}

Where the records go

Client batches and server records meet at the server: /_otel accepts batches up to 256 KB and forwards them with the server's own records. Everything is configured with the standard OpenTelemetry environment variables, so any OTLP/HTTP collector works.

OTEL_EXPORTER_OTLP_ENDPOINT=https://otel.example.com OTEL_EXPORTER_OTLP_HEADERS=x-api-key=secret node dist/server/node.mjs

Never log passwords, tokens, cookies, emails or other personal data, never log inside loops or on every keystroke, and never use console.*: pragma check rejects it with js/console. On a static host there is no /_otel: the client stops sending after the first 404 or 405, while pragma serve always accepts it.
