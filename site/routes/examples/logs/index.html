log in a script

Import log from 'pragma' and call debug, info, warn or error. Keep the message fixed and put the values in attributes.

The browser sends the records in batches to /_otel on the server.

Errors are logged without asking

The runtime logs every uncaught error as ERROR, with its message and stack. No log call needed.

log in load and server actions

load and each server action get log in their argument. An action that throws is logged with its stack.

Without a collector the server prints one JSON line per record. Real output of this route in an app named shop: the load, Approve and Escalate. All records share the page's traceId, taken from the traceparent header.

Logging from utils/

A plain module in utils/ imports the same client logger from .pragma/log.js. Its records join the same batches and trace.

import { log } from '../.pragma/log.js'

export function formatPrice(cents) {
  if (!Number.isInteger(cents)) {
    log.warn('price is not in cents', { 'price.value': cents })
  }
  return (cents / 100).toFixed(2)
}

Where the records go

Client batches go to the server at /_otel (up to 256 KB each), which forwards them with its own records. The standard OpenTelemetry variables configure it, so any OTLP/HTTP collector works.

OTEL_EXPORTER_OTLP_ENDPOINT=https://otel.example.com node dist/server/node.mjs

Never log passwords, tokens, cookies, emails or other personal data, and never log in loops or on each keystroke. console.* fails the check with js/console. On a static host there is no /_otel: the client stops sending after the first 404 or 405.
