Files are routes

The path of a file under routes/ is its URL. index.html maps to the folder, [name] in a file or folder name is a param, and a static segment beats a param: demo/new.html wins over demo/[slug].html for /demo/new. A page is a fragment with optional top-level <title>, <meta> and <link> tags; it has no <html>, <head> or <body>.

FileURL
routes/index.html/
routes/about.html/about
routes/blog/index.html/blog
routes/blog/[slug].html/blog/:slug
routes/blog/[slug]/edit.html/blog/:slug/edit
routes/[lang]/index.html/:lang

Names starting with _ are private; only _layout.html and _404.html are special, any other _x.html is an error. x.html next to x/index.html, or two params in the same folder, is app/route-conflict. There is no [...rest], no optional param and no nested layout.

Dynamic routes with [slug]

The param is params.slug everywhere: in HTML, in the page's <script> after import { params } from 'pragma', and in a load. It is always a URL-decoded string. Reading a param the route does not have is a check error that lists the valid ones. Here a derived function in the page's script finds the post in a local module; with a .server.js the same lookup would run in load (see Data and SSR).

A missing post is data, not an error: the branch renders "not found" and the status stays 200, a soft 404. On static hosting something has to map /demo/abc to [slug].html; pragma serve, the Node adapter and the Workers adapter do it from the manifest.

Route-local components

A component in _components/ next to a route is used as <p-name> by every page in that folder and below: the lookup walks up from the page to routes/. p-post-meta has no <script>, so :post="$post" aliases the page's path at build time and {$post.author} reads through it. Promoting it means moving the folder to lib/components/ and renaming it c-post-meta.

One layout and automatic active links

routes/_layout.html wraps every page. Its optional <head> comes first, is static (a binding there fails check with html/head) and is copied into every page; exactly one <main data-page> holds a lone <slot>. The layout has no <script> and reads only shared, params and query; behavior goes in a component. A <title> in the layout <head> is the fallback for pages without one, and pragma.json's name is the last resort. A page can also write <meta> and <link> at its top level: the build moves them into <head>, replacing the layout's tag with the same name (see SEO and head).

Any routed <a href> without query or hash that points to the current page gets aria-current="page", in the prebuilt HTML and after every navigation. This site styles .nav-link[aria-current="page"] in green: look at the header above, or at the demo nav in any frame on this page.

Tabs and filters live in the query

query.tab holds the query as a string, in HTML and in scripts (import { query } from 'pragma'); a repeated key keeps the last value, and a missing query.x never throws. Links build their URL with href="?tab={tab.id}". Since automatic aria-current ignores links with a query, bind :aria-current to a derived value that is 'true' or false.

Every navigation, including a query-only one, recreates the page state: click the counter, then switch tabs, and it starts again at zero.

Navigating from an action, and full reloads

After an action, navigate(url) from 'pragma' goes through the router like a link click. Use it only when there is no link to click: never a <button> that navigates, location.href or history.pushState. A link with data-reload, target or download, or a click with a modifier key, skips the router and loads the page in full.

The 404 page

A URL that matches no route renders routes/_404.html, served with status 404 by pragma serve and the Node adapter. It is a normal fragment with a <title>; it may have a <script> for state and actions, but never a .server.js. The Workers adapter resolves param routes and answers unknown URLs with this page and a real 404 too.

What the router does for free

  • Intercepts same-origin <a href> clicks and swaps only <main data-page> plus the page's <title>, <meta> and <link> tags, so description, canonical and Open Graph follow the page (SEO and head). The layout stays mounted and its directives are reapplied.
  • Prefetches on hover, on focus and when a link scrolls into view (at idle): the prebuilt HTML plus a modulepreload of the route's modules, which downloads and compiles them without running them until you navigate.
  • Wraps the swap in document.startViewTransition where the browser has it.
  • Scrolls to the top on a new page, restores the position on back and forward, scrolls to #hash targets and moves focus to <main>.

None of it needs code: there is no router to configure, and the pages on this site use nothing else.
